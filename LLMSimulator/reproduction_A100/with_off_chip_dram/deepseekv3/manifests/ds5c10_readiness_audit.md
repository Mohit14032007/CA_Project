### 2.2 Reconciliation of Load Telemetry Concepts

Three distinct telemetry concepts are now unambiguously defined and reconciled:

1. **Linear Invocation (`request_id`):**
   - Each call to `LinearExecutionGPU` is assigned a unique `request_id` (post-incremented at the end of execution).
   - In Stage 1:
     - Pass 1: 16 experts $\times$ 3 linear layers ($W_1, W_3, W_2$) = 48 linear invocations (`request_id` 0 to 47).
     - Pass 2: 16 experts $\times$ 3 linear layers ($W_1, W_3, W_2$) = 48 linear invocations (`request_id` 48 to 95).
     - Total linear invocations = **96 unique `request_id`s**.

2. **Aggregate Rows (`all_weights`):**
   - Exactly one `all_weights` row is generated per linear invocation (total: **96 aggregate rows**).
   - **Off-chip DDR5 batches (misses):** Exactly **16 rows**. During the initial evaluation of $W_1$ for each cold expert, $W_1, W_3, W_2$ are batched into DDR5 (`size_bytes = 88080384`, `memory_source = OFFCHIP_DRAM`, `cache_hit_or_miss = miss`, `duration = 3.901 ms`).
   - **Warm HBM hits:** Exactly **80 rows** (`size_bytes = 29360128`, `memory_source = HBM`, `cache_hit_or_miss = hit`, `duration = 0 ns`).
     - Pass 1 sister hits ($W_3, W_2$): $16 \times 2 = 32$ hits.
     - Pass 2 warm replay hits ($W_1, W_3, W_2$): $16 \times 3 = 48$ hits.
     - Total: $32 + 48 = 80$ hit rows.

3. **Individual Tensor Rows:**
   - Logged for each constituent tensor.
   - For a cold miss (W1 call), all 3 tensors in the batch are logged (`W1_gate`, `W3_up`, `W2_down`): $16 \times 3 = 48$ tensor rows.
   - For an HBM hit, the single executing tensor is logged:
     - Pass 1 sister hits: $16 \times 2 = 32$ tensor rows.
     - Pass 2 replay hits: $16 \times 3 = 48$ tensor rows.
   - Total individual tensor rows = $48 + 32 + 48 = \mathbf{128\text{ rows}}$.
   - Total rows in `expert_load.csv`: $128\text{ tensor rows} + 96\text{ aggregate rows} = \mathbf{224\text{ data rows}}$ (plus 1 header row = 225 lines).

### 2.3 Cache Events Reconciliation

Total cache events in `expert_cache.csv`: **112 events**.
- `MISS`: **16 events**. Initial probe by $W_1$ for each of the 16 cold experts.
- `INSERT`: **16 events**. Logged once per cold expert strictly upon completion of the Ramulator batch.
- `HIT`: **80 events**.
  - Pass 1 sister evaluations ($W_3, W_2$): $16 \times 2 = 32$ hits.
  - Pass 2 replay evaluations ($W_1, W_3, W_2$): $16 \times 3 = 48$ hits.
- `EVICT`: **0 events** (HBM capacity is 80 GB; 16 resident experts occupy $1.409\text{ GB} \ll 80\text{ GB}$).
- **Final Resident Bytes:** $16 \times 88,080,384 = \mathbf{1,409,286,144\text{ bytes}}$ ($\approx 1.409\text{ GB}$).
- **Crucial Correctness Invariant:** Exactly the 16 routed experts are resident in cache. Unrouted experts with empty activations never called cache functions and left zero footprint.

### 2.4 Timestamp & Latency Semantics

- In `expert_load.csv`, the durations for $W_1$, $W_3$, and $W_2$ within a cold batch represent **cumulative completion times measured from the batch start**:
  - $W_1$ completion: $\approx 1.3006\text{ ms}$
  - $W_3$ completion: $\approx 2.6005\text{ ms}$
  - $W_2$ completion: $\approx 3.9013\text{ ms}$
  - Batch duration (`all_weights`): $\approx 3.9013\text{ ms}$
- Timestamps must NOT be summed ($1.3 + 2.6 + 3.9 \neq 7.8\text{ ms}$). The true simulated transfer duration for all 3 weights is the batch completion duration of $\approx 3.901\text{ ms}$.
- Total simulated DDR5 time for Pass 1: $16 \times 3.901028\text{ ms} = \mathbf{62.41645\text{ ms}}$.
- Host wall-clock time for Pass 1: $164.1444\text{ s}$.
- Host wall-clock time for Pass 2 (Warm Replay): $0.0118\text{ s}$ (100% cache hits, zero Ramulator simulation required).

## 4. Full Workload Preflight Calculations (DeepSeek-V3 Baseline)

- Model: DeepSeek-V3
- Total Transformer Layers: 60
- First-K Dense Layers: 3 (Layers 0, 1, 2)
- Total MoE Layers: $60 - 3 = 57$ (Layers 3 through 59)
- Routed Experts per MoE Layer: 256
