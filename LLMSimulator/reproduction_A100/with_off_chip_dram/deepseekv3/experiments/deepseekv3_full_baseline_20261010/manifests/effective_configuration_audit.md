## 1. Executive Summary: The "Main Configuration File" Resolution

A central question prompting this audit is whether the file:
```
build/config.yaml
```
(which specifies `gpu_gen: B100`, `num_device: 8`, `precision_byte: 1`, and `use_ramulator: off`) was the configuration file that governed the completed DeepSeek-V3 full-baseline experiment.

### Definitive Audit Finding:
> [!IMPORTANT]
> **`build/config.yaml` was completely UNUSED and HAD ZERO EFFECT on the completed full-baseline run.**
>
> 1. `build/config.yaml` is a build artifact generated by CMake (`CMakeLists.txt:30: configure_file(config.yaml ${EXECUTABLE_OUTPUT_PATH}/config.yaml COPYONLY)`), intended strictly for the generic test driver `eval/test.cpp` (which builds the binary `./build/run`).
> 2. The full baseline executable that executed the 74-minute run is `./build/test_deepseekv3_full_baseline`, compiled from `eval/test_deepseekv3_full_baseline.cpp`.
> 3. `eval/test_deepseekv3_full_baseline.cpp` does **not** include `<yaml-cpp/yaml.h>`, does **not** call `YAML::LoadFile("config.yaml")`, accepts **no** configuration file arguments, and reads **no** model-level YAML file whatsoever.
> 4. Instead, the model parameters and system settings were **constructed and assigned directly in C++** within `eval/test_deepseekv3_full_baseline.cpp` and `src/model/model_config.h`.
> 5. The only configuration files loaded at runtime were two Ramulator 2 memory YAMLs:
>    - **DDR5 Secondary Tier:** `config_snapshot/dram_config_DDR5_retry.yaml`, passed dynamically via the `OFFCHIP_DRAM_CFG` environment variable set in `run_full_baseline.sh`.
>    - **HBM Primary Tier:** `./dram_config_HBM3_80GB.yaml` (in the repository root), loaded via a hardcoded path inside `src/hardware/device.cpp:35`.

## 4. Answers to Mandatory Audit Questions

### 1. Is `build/config.yaml` the main configuration for the completed experiment?
**NO.** `build/config.yaml` had no role in this experiment. It is generated by CMake for the generic `./build/run` driver (`eval/test.cpp`). The full baseline ran `./build/test_deepseekv3_full_baseline`, which never opens or parses `build/config.yaml`.

### 2. Does `test_deepseekv3_full_baseline.cpp` load a model-level YAML?
**NO.** `test_deepseekv3_full_baseline.cpp` does not include `<yaml-cpp/yaml.h>`, does not call `YAML::LoadFile`, accepts no command-line arguments, and does not parse any model YAML.

### 3. Does the executable construct the model configuration directly in C++?
**YES.** All model parameters (`hidden_dim = 7168`, `expert_intermediate_dim = 2048`, `num_layers = 60`, `first_k_dense = 3`, `num_routed_expert = 256`, `top_k = 8`, `precision_byte = 2`, `ffn_way = 3`, `dataset = "synthesis"`) are instantiated and assigned directly in C++ in `eval/test_deepseekv3_full_baseline.cpp:66-81`.

### 4. Which exact DDR5 YAML was loaded at runtime?
**The file passed via the `OFFCHIP_DRAM_CFG` environment variable by `run_full_baseline.sh`:**
```
/home/mohman/ca_project/LLMSimulator/reproduction_A100/with_off_chip_dram/deepseekv3/experiments/deepseekv3_full_baseline_20261010/config_snapshot/dram_config_DDR5_retry.yaml
```
(SHA-256: `7ef030f82d7f654339aa0ab1ff31abce311322c59aee693eb57774e071db9d97`). It was loaded by Ramulator 2 in `src/hardware/device.cpp:72` via `DRAMInterface::Create`.

### 5. Is `dram_config_HBM3_80GB.yaml` actually read by the execution path or merely saved as a snapshot?
**BOTH, with an important path distinction:**
- **Actually read:** The runtime executable path in `src/hardware/device.cpp:35,40` executed `YAML::LoadFile("./dram_config_HBM3_80GB.yaml")`. Because the runner executed from the repository root (`cd /home/mohman/ca_project/LLMSimulator`), the file actually read from disk was `/home/mohman/ca_project/LLMSimulator/dram_config_HBM3_80GB.yaml`.
- **Snapshot copy:** The file inside `config_snapshot/dram_config_HBM3_80GB.yaml` is a verified bit-for-bit duplicate (SHA-256: `e7ae1fb6...`), but its specific filepath was **not** accessed by the executable. Furthermore, HBM access was modeled with 0 ns latency for resident expert hits, so the HBM timing engine registered zero elapsed cycles.

### 6. Which file should I edit to change the model used in a future run?
If using the existing `test_deepseekv3_full_baseline` binary workflow:
Edit **`eval/test_deepseekv3_full_baseline.cpp`** (lines 66–81 for model attributes, lines 253–254 for layer counts), then recompile with `cmake --build build --target test_deepseekv3_full_baseline`.  
*(See Section 6 for our recommendation to migrate this to an external YAML).*

### 7. Which file should I edit to change DDR5 hardware settings?
Edit the YAML pointed to by `OFFCHIP_DRAM_CFG` in `run_full_baseline.sh:11`, specifically:
`reproduction_A100/with_off_chip_dram/configs/dram_config_DDR5_retry.yaml` (or the snapshot YAML for experiment-local edits). In addition, if changing memory bus geometry (channels, ranks, banks, rows), update `ddr5_32gb_x16_2ch` in **`src/dram/memory_config.h`**.

### 8. Which configuration file, if any, controls the FP16-versus-FP8 accounting?
**No configuration file controls this.** It is controlled by the hardcoded C++ statement in **`eval/test_deepseekv3_full_baseline.cpp` at line 77**:
```cpp
model_config.precision_byte = 2; // FP16
```
(Changing this to `model_config.precision_byte = 1;` switches the accounting to FP8).

## 6. Recommendation for Future Experiments: Dedicated Unified Configuration Setup

To avoid configuration ambiguity in future runs, we recommend establishing a single, authoritative experiment YAML structure under:
```
reproduction_A100/with_off_chip_dram/deepseekv3/configs/
```

### Proposed Schema (`experiment_deepseekv3_60layer_full.yaml`):
```yaml
experiment:
  name: "deepseekv3_full_baseline"
  classification: "DeepSeek-V3-shaped, 60-layer, FP16, synthetic-routing memory-system simulation"

model:
  model_name: "deepseekV3"
  total_layers: 60
  first_k_dense: 3
  moe_layers: 57
  routed_experts_per_layer: 256
  top_k: 8
  shared_experts: 1
  hidden_dim: 7168
  expert_intermediate_dim: 2048
  ffn_way: 3
  precision_byte: 2 # 2 for FP16, 1 for FP8

system:
  gpu_gen: "A100"
  num_device: 1
  processor_type: "GPU"
  use_ramulator: true
  cache_capacity_bytes: 80000000000 # 80 GB

memory_tiering:
  offchip_dram_config: "reproduction_A100/with_off_chip_dram/configs/dram_config_DDR5_retry.yaml"
  onchip_hbm_config: "dram_config_HBM3_80GB.yaml"

workload:
  dataset: "synthesis"
  input_len: 1
  output_len: 2
  skewness: 0.0
  pass_count: 2
  deterministic_replay: true
```

### Code Implementation Recommendation (For Future Revisions):
1. In future evaluation harnesses, accept `argv[1]` as an optional path to this experiment YAML.
2. If provided, populate `ModelConfig` and `SystemConfig` directly from the YAML fields using `yaml-cpp`.
3. In `Device::Device` (`src/hardware/device.cpp`), update `dram_cfg_path` to accept a configurable path rather than hardcoding `./dram_config_HBM3_80GB.yaml`.

## 7. Audit Conclusion

The completed DeepSeek-V3 full-baseline experiment was executed with total architectural and mathematical integrity. The discrepancy between `build/config.yaml` and the experiment results is explained by the fact that `build/config.yaml` belongs to a different executable (`./build/run`), while the authoritative baseline executable (`./build/test_deepseekv3_full_baseline`) drew its parameters directly from explicit C++ configuration logic in `eval/test_deepseekv3_full_baseline.cpp` and runtime DDR5 YAML configuration passed via environment variable.
